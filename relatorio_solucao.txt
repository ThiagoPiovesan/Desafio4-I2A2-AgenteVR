## 2. Como a Solução foi Construída

A solução foi desenvolvida em Python, utilizando o conceito de **agentes de IA** para modularizar e automatizar as tarefas de processamento de dados e de cálculo. A escolha por essa abordagem visa delegar a interpretação de regras de negócio complexas a um modelo de linguagem (LLM), tornando o sistema mais flexível e adaptável a futuras mudanças.

Os principais componentes são:

*   **Orquestrador (`main.py`):** É o ponto de entrada da aplicação. Ele gerencia o fluxo de execução, inicializa os agentes na ordem correta e passa os dados de um para o outro. Primeiro, ele aciona o `Agente de Dados` para obter um DataFrame consolidado e, em seguida, entrega esse DataFrame ao `Agente de Cálculo` para a aplicação das regras.

*   **Agentes (`src/agente_*.py`):** São o núcleo da solução. Foram construídos utilizando a biblioteca LangChain, que facilita a interação com a API do Google Gemini. Cada agente é especializado em uma macro-tarefa (um para dados, outro para cálculos) e é guiado por um prompt específico que detalha suas responsabilidades e objetivos.

*   **Ferramentas (`src/agente_dados_tools.py`):** Para permitir que o `Agente de Dados` interaja com o sistema de arquivos, foram criadas ferramentas customizadas (usando a anotação `@tool` do LangChain). Essas ferramentas dão ao agente a capacidade de listar arquivos em um diretório e ler o conteúdo de planilhas, ações essenciais para sua tarefa.

*   **Prompts (`utils/*.txt`):** São arquivos de texto que contêm as instruções em linguagem natural para cada agente. Essa abordagem desacopla a lógica de negócio do código-fonte, permitindo que as regras sejam alteradas sem a necessidade de modificar o código Python.
    *   `prompt_agente_dados.txt`: Instrui o agente a encontrar, ler e consolidar os arquivos de entrada.
    *   `llm_prompt.txt`: Contém o detalhamento completo das regras de cálculo do VR.

*   **Configuração (`src/config.py`):** Centraliza os caminhos de diretórios e outras configurações, facilitando a manutenção do projeto.

## 3. Passo a Passo para Montagem e Execução

### Pré-requisitos

*   Python 3.9 ou superior
*   Poetry (ou outro gerenciador de ambiente virtual como o UV)

### Passos

1.  **Clonar o Repositório:**
    ```bash
    git clone <url-do-repositorio>
    cd Desafio4
    ```

2.  **Instalar Dependências:**
    Utilize o Poetry para criar um ambiente virtual e instalar todas as bibliotecas listadas no arquivo `pyproject.toml`.
    ```bash
    poetry install
    ```

3.  **Configurar a Chave de API:**
    *   Na raiz do projeto, crie um arquivo chamado `.env`.
    *   Dentro deste arquivo, adicione sua chave da API do Google Gemini da seguinte forma:
        ```
        GOOGLE_API_KEY="SUA_CHAVE_DE_API_AQUI"
        ```

4.  **Adicionar os Dados de Entrada:**
    *   Certifique-se de que todas as planilhas Excel com os dados dos colaboradores estejam localizadas no diretório `data/input/`.

5.  **Executar a Solução:**
    Com o ambiente virtual ativado, execute o script principal.
    ```bash
    poetry run python main.py
    ```
    Alternativamente, você pode ativar o shell do ambiente primeiro:
    ```bash
    poetry shell
    python main.py
    ```
O processo completo pode levar alguns minutos. Ao final, o arquivo `vr_unificado.csv` será gerado no diretório `data/output/`.

## 4. Indicação Clara e Objetiva do Uso dos Agentes

Os agentes são os componentes centrais que executam as duas principais etapas do processo. Eles são utilizados da seguinte forma:

### Agente 1: Agente de Dados (`src/agente_dados.py`)

*   **Onde é usado?** É o primeiro agente a ser invocado pelo `main.py`.
*   **Como é usado?** Sua função é preparar os dados para o cálculo. Ele recebe um prompt (`prompt_agente_dados.txt`) que o instrui a:
    1.  Usar suas ferramentas (`agente_dados_tools.py`) para listar os arquivos no diretório `data/input/`.
    2.  Identificar e ler cada uma das planilhas relevantes (ativos, férias, etc.).
    3.  Consolidar todas as informações lidas em um único DataFrame (usando a biblioteca Pandas).
    4.  Retornar este DataFrame unificado para o orquestrador (`main.py`).

### Agente 2: Agente de Cálculo (`src/agente_calculo.py`)

*   **Onde é usado?** É o segundo agente, invocado pelo `main.py` logo após a conclusão do Agente de Dados.
*   **Como é usado?** Sua função é executar a lógica de negócio. Ele recebe o DataFrame unificado e um prompt (`llm_prompt.txt`) com todas as regras de cálculo. Guiado por este prompt, ele executa código Python para:
    1.  Calcular os dias úteis para cada colaborador.
    2.  Descontar dias de férias, afastamentos e feriados.
    3.  Aplicar regras de pagamento proporcional para colaboradores recém-admitidos ou desligados.
    4.  Calcular o valor final do benefício com base no estado (UF) do sindicato.
    5.  Gerar um novo DataFrame com os resultados dos cálculos, que é então retornado ao `main.py` para ser salvo como o arquivo de saída.
